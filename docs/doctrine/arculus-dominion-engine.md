# Arculus Dominion Engine

**Source:** [`critter2881/arculus-dominion-engine`](https://github.com/critter2881/arculus-dominion-engine).

## Purpose

The intended authority and enforcement layer of Prometheus: it defines what is allowed, what is forbidden, what advances ("ascends"), and what is rejected, and it keeps every engine aligned with PCI's identity architecture (the "Ascension Law").

## The five layers

| Layer | Role |
|-------|------|
| Authority: Sovereign Law Engine | Structural laws, doctrine enforcement, ascension gating |
| Control: Behavioral Regulator | Engine behavior, escalation, execution boundaries |
| Synchronization: Multi-Engine Unifier | Unifies Runtime, Funnel, OQA, PCI, and downstream engines |
| Dominion Logic: Enforcement Spine | Sovereign rules, rejection criteria, identity-locked behavior |
| Deployment | Integration into PCI, Prometheus, OQA, and Whop distribution |

A five-module course outline accompanies it: architecture foundations, authority systems and execution governance, multi-engine synchronization, deployment and integration, and mastery.

> **Status.** The source repository is a README only. The practical enforcement mechanisms that exist in *this* repository are: CI gates, [minting safeguards](../guide/07-arcana-nfts-and-arcanapass.md), cross-check review flags in Prometheus, [quant verification](../guide/15-github-automation.md), and the [privacy guard test](../../tests/test_privacy.py).
